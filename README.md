# Data Migration PoC

Proof of concept for migrating historical CSV data into a SQL database, with a
REST API to ingest new records, AVRO-based table backup and restore, and
hiring metrics endpoints.

## What it does

| Requirement | How |
| --- | --- |
| Move historical CSV data to the database | `app/load_csv.py` |
| REST API for new rows, 1 to 1,000 rows per request, for any table | `POST /tables/{table}` in `app/api.py` |
| Rows that break the data rules are not inserted, but logged | `rejected_rows` table |
| Back up a table to AVRO | `app/backup.py backup` |
| Restore a table from a backup | `app/backup.py restore` |
| Hires per department and job in 2021, by quarter | `GET /metrics/hires-by-quarter` |
| Departments that hired more than the 2021 mean | `GET /metrics/departments-above-mean` |

## Project structure

```text
app/
  models.py      data rules for each table, shared by the loader and the API
  db.py          inserts rows and logs the rejected ones
  load_csv.py    loads the historical CSV files
  api.py         REST API (FastAPI)
  backup.py      AVRO backup and restore
sql/
  schema.sql     tables, keys and constraints
  metrics/       SQL queries for the metrics endpoints
profiling/       SQL queries used to profile the raw data (DuckDB)
docs/
  data_profile.md   profiling report and schema decisions
  aws_architecture.md   design to run the project on AWS
  raw_data.sha256   checksums of the raw files
Dockerfile
docker-compose.yml
```

## Design decisions

The schema is based on a profile of the raw data. Every decision comes from a
finding, and the details are in [docs/data_profile.md](docs/data_profile.md).
In short:

- **Target database:** PostgreSQL.
- **Data rules in one place:** `app/models.py` defines the rules for each table.
  The CSV loader and the API use the same rules.
- **Two levels of validation:** Python checks required fields and types; the
  database checks duplicate ids and foreign keys. Each rejected row is stored in
  `rejected_rows` with the original values, the reason, and the source (`csv` or
  `api`).
- **Ids from the source are kept:** they are not generated by the database.
- **Foreign keys without `ON DELETE CASCADE`:** deleting a department or job
  that has hires fails, instead of deleting those hires.
- **Dates in UTC:** `datetime` is stored as `TIMESTAMPTZ`, and the metrics use
  UTC for year and quarter. With another time zone, 4 hires at the start of
  2022 would count as 2021.

## Quick start with Docker

Requirements: Docker with Docker Compose.

1. Put the raw CSV files in `data/raw/`, and create the configuration:

   ```bash
   cp .env.example .env
   ```

   Set `POSTGRES_PASSWORD` in `.env`. If the password contains `$`, put it in
   single quotes.

2. Start the database and the API. The schema is created automatically:

   ```bash
   docker compose up -d --build db api
   ```

3. Load the historical data (runs once):

   ```bash
   docker compose run --rm loader
   ```

4. Open the API documentation: http://127.0.0.1:8080/docs

The database is published on port 5433, so it can be opened with a SQL client.
Back up and restore a table inside the API container. The backups are kept
in the `backups` volume:

```bash
docker compose exec api python -m app.backup backup hired_employees
docker compose exec api ls backups
docker compose exec api python -m app.backup restore hired_employees backups/hired_employees_<timestamp>.avro
```

To copy the backups to your computer:

```bash
docker compose cp api:/app/backups ./backups
```

To stop everything and delete the database and backup volumes:

```bash
docker compose down -v
```

## Setup without Docker

Requirements: Python 3.12, [uv](https://docs.astral.sh/uv/), PostgreSQL.

1. Install the dependencies:

   ```bash
   uv sync
   ```

2. Put the raw CSV files in `data/raw/` and check them:

   ```bash
   shasum -a 256 -c docs/raw_data.sha256
   ```

3. Create the configuration from the template, and edit it:

   ```bash
   cp .env.example .env
   ```

   The password is not stored in the project. It is read from `~/.pgpass`.

4. Create the database and the tables:

   ```bash
   createdb data_migration_poc
   psql -d data_migration_poc -f sql/schema.sql
   ```

## Usage

The examples use the local setup. With Docker, the API is on port 8080
instead of 8000.

### Load the historical data

```bash
uv run python -m app.load_csv
```

Result with the provided files: 1,929 rows inserted and 70 rejected, as
expected from the data profile. The load runs only once: it stops if the tables
already have data.

### Run the API

```bash
uv run uvicorn app.api:app --reload
```

Interactive documentation: http://127.0.0.1:8000/docs

Insert a batch:

```bash
curl -X POST http://127.0.0.1:8000/tables/departments \
  -H "Content-Type: application/json" \
  -d '[{"id": 13, "department": "Data Engineering"}]'
```

Response:

```json
{"table": "departments", "received": 1, "inserted": 1, "rejected": 0}
```

Read the metrics:

```bash
curl http://127.0.0.1:8000/metrics/hires-by-quarter
curl http://127.0.0.1:8000/metrics/departments-above-mean
```

### Back up and restore a table

```bash
uv run python -m app.backup backup hired_employees
uv run python -m app.backup restore hired_employees backups/hired_employees_<timestamp>.avro
```

The restore runs in one transaction. If it would break a foreign key, it is
cancelled and nothing changes.

## Assumptions

- The second metric counts hires in 2021, the same period as the mean.
- Dates must include a time zone. A date without one is rejected, because it
  could mean different moments.
- Text values are trimmed before they are checked.
- The rows in `rejected_rows` from the API keep the values as they arrived.

## Security

- No password in the project: the local setup uses `~/.pgpass`, and Docker
  reads the password from `.env`, which is not committed.
- SQL values are always sent as parameters, and table names are composed with
  `psycopg.sql`, so the input cannot change the SQL.
- The table name in the API is limited to the three tables.
- Each request accepts at most 1,000 rows.
- Backup and restore are command-line tools, not API endpoints, because a
  restore replaces a whole table.
- The container runs as a non-root user, and the image does not include `.env`
  or the data files.

## Next steps

- **Faster loading:** the loader inserts row by row. Over a home network it
  took about 26 seconds for 1,999 rows; inside Docker, next to the database,
  it took less than a second. The time is in the round trips, so for large
  files I would validate the rows and load them with `COPY`.
- **API authentication:** for example, an API key or OAuth2 tokens, and HTTPS.
- **Error responses:** do not return the full request body in validation errors.
- **Automated tests** with pytest, run in GitHub Actions.
- **Cloud deployment on AWS:** raw files in S3, the database in RDS, the API on
  ECS, the password in Secrets Manager, and logs in CloudWatch. The design is
  in [docs/aws_architecture.md](docs/aws_architecture.md).
- **Visual report** for the metrics.
